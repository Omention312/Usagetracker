## 一、目标定义与平台

### 1.1 要解决的问题

回答两个问题:“这个程序**今天开了多久**”(总运行时长,含在后台挂着的时间)与“我**实际用它用了多久**”(前台占用时长),并按天/程序/浏览器站点做统计,用于个人时间审计与自我管理。

### 1.2 平台假设(已确认,不再讨论)

- **Windows 10 / 11, x64**;单机;单用户交互会话;个人电脑;标准(非管理员)权限运行。
- 不开机自启为系统服务,以**用户态常驻托盘程序**方式运行(HKCU 注册表自启,无需管理员)。
- 影响:只面向交互会话(Session 1+),忽略服务会话(Session 0)与其他用户;不处理多用户、远程桌面多会话等场景。

### 1.3 语言决策(按用户规则裁定)

用户规则:若“先 Python、后期转 C#”困难且耗 token → 直接选 C#,否则先做 Python 版。

**评估结论**:
- v2 范围需要:无管理员进程启停检测、Edge 地址栏 UIA 域名提取、SQLite、托盘、自启动、备份恢复。若 Python 先行,监测引擎与 Edge 域名提取(UIA)两块在转 C# 时**几乎整体重写**(两语言 API/线程模型完全不同),且需重新跑全部验收,迁移成本 ≈ 初次开发的 5~7 成。
- 属于“比较困难/较耗 token”→ **规则命中,直接定稿 C#/.NET 8**,省掉二次迁移。

> 例外:若主人想自己阅读/修改 Python 代码并接受长期留在 Python,可以推翻本裁定——告诉我即可。

### 1.4 术语口径(全文统一)

| 术语 | 定义 |
|---|---|
| **运行时长 / 总时长** | 进程从启动到退出的墙钟时长(前台+后台都算) |
| **使用时长 / 前台时长** | 该进程窗口位于**最前台**的时间,即统计里的“使用时间” |
| **后台时段** | 进程在运行、但不在最前台的时间(计入运行时长,不计入使用时长) |
| 不做的事 | 输入检测、活跃/空闲判定、锁屏空闲剔除、窗口标题采集 |

> 说明:选择“前台+后台都要”后,仍不引入任何输入检测——前台时间一律算“使用”,不判断人在不在(第二章 2.3 确认)。

## 二、功能范围

### 2.1 记录的信息(只这两类事实 + 一个特例)

**① 进程运行会话层**(回答“开了多久、什么时候开/关”)
| 字段 | 说明 |
|---|---|
| PID + 进程创建时刻 | 联合主键,解决 PID 复用(见 6.2) |
| 可执行文件路径 / 显示名 | `chrome.exe` / `Code.exe` |
| 会话 ID、父进程 PID | 区分交互会话;辅助识别“用户启动的应用” |
| 启动时间 / 结束时间 | 精确到秒级(快照差分,见 3.3) |
| 退出方式 | 正常 / 异常(被强杀、闪退) |
| 是否系统进程 / 是否忽略 | 过滤标记 |

**② 前台占用层**(回答“实际用了多久”)
| 字段 | 说明 |
|---|---|
| 前台时间段 [ts_from, ts_to) | 该应用窗口位于最前台的连续时段 |
| 前台/后台状态 | 打开的应用只记录这一状态;无窗口标题 |

**③ Edge 浏览器域名特例**(见 2.2)

### 2.2 Edge 浏览器域名适配(唯一保留的“窗口级”信息)

目标:**简单**记录浏览器使用情况,按“规范化站点”归并统计。

规则:
1. 仅当**前台窗口属于 Edge**(`msedge.exe`)时启用;其余时刻不采集任何 URL。
2. 每 2 秒读取 Edge 地址栏的当前 URL(UI Automation,见 3.4),取 host 做规范化:
   - 小写、去端口、去 tracking 参数(URL 仅用于取 host,**完整 URL 一律不落库**,见 6.5);
   - **折叠**:所有子域名与裸域名折叠为 `www.<主域>`。内置主域判定使用公共后缀折叠 + 可配置归并表。
   - 示例:`space.bilibili.com`、`www.bilibili.com`、`bilibili.com`、`t.bilibili.com` → **全部记 `www.bilibili.com`**。
3. 非网页内容(`edge://`、新标签页、开发者工具、本地文件、无 URL)→ 该时段**不计域名**,仍记为应用 `Microsoft Edge`。
4. 读取失败的降级链:UIA 读地址栏 → 窗口标题正则(`... - <host> - Microsoft Edge` 形态,尽力而为)→ 仍失败记 `Microsoft Edge(未知页面)`。

效果:统计时既能看“Edge 开了多久”,也能看“今天在 bilibili 待了多久”(按 www.bilibili.com 计),规则只此一条,不做通用网页分类。

### 2.3 不做输入检测

删除 `GetLastInputInfo` 及空闲/活跃概念。前台占用即“使用”,口径简单、可解释、易验收。

### 2.4 需要支持的查询与统计

- 按时间范围筛选(任意起止);
- 按程序 / 按 Edge 站点聚合;
- 指标:前台时长、总运行时长、启动次数、按日趋势(近 30 天)。
- 不做:导出(2.5)、分类规则引擎、多应用同时计费(同一时刻只认一个前台)。

### 2.5 明确不做的功能(范围红线)

| 不做 | 说明 |
|---|---|
| 导出功能 | 不提供 CSV/JSON/库副本导出 |
| Web 仪表板 | 不提供常驻本地 HTTP 服务 + ECharts 仪表板(见 2.6 的静态 HTML 替代) |
| 窗口标题 | 除 2.2 Edge 域名外一律不采 |
| 输入/空闲检测 | 见 2.3 |
| 分类规则引擎 | 不做 工作/娱乐 自动分类(保留“忽略名单”用于隐私,见 6.5) |
| 跨设备/云 | 纯本地 |

### 2.6 展示方式(砍 Web 仪表板后)

| 方式 | 说明 | 是否保留 |
|---|---|---|
| 托盘常驻 + “今日概览”弹窗 | 单击托盘:今日总使用时长、前台 Top5、当前应用、今日 Top 站点 | ✅ 主界面 |
| CLI 查询 | `usage today` / `usage top --days 7` / `usage app <名称>` / `usage report` | ✅ |
| 本地静态 HTML 报表(可选) | 按需生成一份**自包含** HTML(内嵌图表)并用默认浏览器打开;**无常驻服务**,属“查看”而非“导出” | 🟡 可选 |
| 常驻 Web 仪表板 | v1 方案③ | ❌ 已砍 |

### 2.7 自动备份(硬需求)

详见 4.5——每日自动备份、保留最近 N 份、损坏自检与一键恢复。**此项为必须功能,不砍。**

## 三、技术方案

### 3.1 总体架构(v2)

```
用户态常驻程序(托盘,无管理员)
┌────────────────────────────────────────────────────────┐
│ ① 前台归属监测器       1 s 轮询                         │
│    GetForegroundWindow → 属主 PID → exe 名/显示名        │
│    └ 若为 Edge → ② Edge 域名采样器(2 s,UIA 读地址栏)      │
│ ③ 生命周期监测器       3~5 s 快照差分                    │
│    NtQuerySystemInformation(SystemProcessInformation)   │
│    以 (PID, CreateTime) 为主键 → 启动/退出事件            │
│ ④ 恢复/对账模块         启动时封口残留、睡眠/断电补齐      │
│ ⑤ 写入层               SQLite(WAL,单写者,变化才写)       │
│ ⑥ 展示层               托盘今日概览 + CLI + 可选静态HTML  │
│ ⑦ 备份层               每日 VACUUM INTO + 滚动保留 + 自检 │
└────────────────────────────────────────────────────────┘
数据目录:%LOCALAPPDATA%\UsageTracker\(usage.db、backups\)
```

要点:**运行时长事实(③)与使用时长事实(①)分离记录**,统计层按时间轴对账得到“前台时长 / 总运行时长 / 后台时长”。

### 3.2 前台归属监测(①)

```text
每 1 秒:
  hwnd = GetForegroundWindow()
  空 → 状态=锁屏/无前台:当前前台片段封口(不计任何应用)
  否则 GetWindowThreadProcessId(hwnd, &pid) → 显示名(路径缓存,避免每拍 OpenProcess)
  若 pid/应用 与上一拍相同 → 延续片段;不同 → 封口上一片段、开新片段
每 60 秒强制 checkpoint 一次(防断电丢最后 1 分钟)
```

- 全屏游戏(含独占全屏):`GetForegroundWindow` 依然返回游戏窗口,天然兼容,无需特判。
- 锁屏 / UAC:`LogonUI`/`consent.exe` 或前台消失 → 封口,该时段不归属任何应用。

### 3.3 进程生命周期监测(③,无管理员)

```text
每 3~5 秒:NtQuerySystemInformation(SystemProcessInformation)
  返回全系统进程快照: PID、父PID、CreateTime、SessionId、映像名
与上一帧做差分(主键 = (PID, CreateTime)):
  新增 → 启动事件:记录 exe/路径/启动时刻,建“运行会话”
  消失 → 退出事件:封口该会话(结束时刻、退出方式)
过滤:Session 0 / 系统白名单(svchost、dwm、csrss…)/ 本程序自身 → 打标但不参与使用统计
```

- 该 API 无需管理员即可拿到全系统进程的**创建时间**(解决 PID 复用,也不需要 OpenProcess)。
- “后台时段”不单独落库:统计时由 运行会话(③)与前台片段(①)按时间轴对账得出。

### 3.4 Edge 域名采样(②,关键技术点)

- 触发条件:前台归属判定为 Edge 时才开始采样,切走即停(几乎零常驻开销)。
- 读取方式:**UI Automation**(`System.Windows.Automation`):在 Edge 前台窗口树中查找地址栏控件(名称形如“地址和搜索栏”/“Address and search bar”),取其 `ValuePattern` 得当前 URL。
- 频率 2 s;仅在片段封口时把**规范化 host** 写入前台片段行(2.2 规则)。
- **M0 必须做 spike 验证**(见 8.1):确认该 UIA 读取在“Edge 前台但地址栏未聚焦”时可用;不可用则启用降级链(标题正则 → 未知页面)。此点不 mock,实测为准。

### 3.5 边界情况处理清单(v2)

| 边界 | 行为 |
|---|---|
| 后台进程 / 服务 | 计入该进程的**运行会话**,但不是前台 → 不计使用时长 |
| 系统级进程 | 白名单 + Session 0 过滤,不入库或打标忽略 |
| 游戏全屏(窗口化/独占) | 前台轮询天然兼容,无需特判 |
| 反作弊游戏拒绝读取路径 | 用快照中的映像名 + 启动时路径缓存兜底,按名计费 |
| UWP / Store 应用 | 前台窗口宿主特判(ApplicationFrameHost → 真实应用进程/UAM 映射);识别失败按宿主名计费 |
| 闪退 / 被强杀 | 进程从快照消失 → 会话封口(exit_kind=异常);时长照常计入 |
| 无响应 | 不做检测(与计费口径无关),如需再议 |
| PID 复用 | (PID, CreateTime) 主键,杜绝串账 |
| 多实例 | 生命周期按实例;统计按显示名聚合 |
| 锁屏 / UAC | 前台消失或为系统前台 → 封口,不归属应用 |
| 睡眠 / 断电 | 心跳大跳变 → 片段封口到跳变前;启动对账补齐(见 4.4) |
| 程序升级改名 exe | 显示名变化按“新程序”处理;不做合并引擎(用户可加忽略名单,见 6.5) |

### 3.6 技术栈明细(C#)

| 组件 | 选型 |
|---|---|
| 语言/框架 | C# + .NET 8 (`net8.0-windows`,WinForms 或 WPF) |
| 前台/窗口 | `user32` P/Invoke:GetForegroundWindow、GetWindowThreadProcessId |
| 生命周期 | `ntdll` P/Invoke:NtQuerySystemInformation(SystemProcessInformation),快照差分 |
| Edge 域名 | `System.Windows.Automation`(UIAutomationClient) |
| 数据库 | `Microsoft.Data.Sqlite`(SQLite 原生库) |
| 托盘 UI | WinForms `NotifyIcon`(最轻) + 今日概览窗体 |
| 自启动 | 注册表 `HKCU\...\Run`(无管理员) |
| 单实例 | `Mutex` |
| 发布 | framework-dependent(装 .NET 8)或 self-contained 单文件(自选) |

> 无管理员、无 ETW、无服务安装——全部能力在普通权限下实现。

## 四、数据存储与格式

### 4.1 存储选型

SQLite 单文件 `usage.db`,WAL 模式。数据目录 `%LOCALAPPDATA%\UsageTracker\`;备份目录 `backups\`。

### 4.2 表结构(DDL v2)

```sql
PRAGMA journal_mode=WAL;
PRAGMA synchronous=NORMAL;

-- 应用注册表:显示名、忽略标记(隐私名单;无分类引擎)
CREATE TABLE app_info (
  exe_hash   TEXT PRIMARY KEY,        -- exe SHA-256 前 16 hex
  exe_path   TEXT,
  app_name   TEXT NOT NULL,           -- 归一显示名:Chrome / Code / Microsoft Edge
  is_ignored INTEGER DEFAULT 0        -- 忽略名单(不参与统计但保留原始)
);

-- ① 进程运行会话(前台+后台的完整运行时长)
CREATE TABLE process_sessions (
  id         INTEGER PRIMARY KEY,
  pid        INTEGER NOT NULL,
  pid_born   INTEGER NOT NULL,        -- 进程创建时刻(epoch ms),与 pid 联合身份
  exe_hash   TEXT REFERENCES app_info(exe_hash),
  app_name   TEXT NOT NULL,
  session_id INTEGER,
  parent_pid INTEGER,
  started_at INTEGER NOT NULL,        -- epoch ms
  ended_at   INTEGER,                 -- NULL=运行中(启动对账封口)
  exit_kind  INTEGER DEFAULT 0        -- 0 未知 1 正常 2 异常/被终止
);
CREATE INDEX idx_ps_time ON process_sessions(started_at);

-- ② 前台占用片段(使用时长事实;Edge 站点记在 domain)
CREATE TABLE foreground_segments (
  id        INTEGER PRIMARY KEY,
  ts_from   INTEGER NOT NULL,         -- epoch ms
  ts_to     INTEGER NOT NULL,         -- 相邻片段无缝:上条 ts_to == 本条 ts_from
  pid       INTEGER,
  pid_born  INTEGER,
  app_name  TEXT NOT NULL,            -- 应用显示名
  domain    TEXT                      -- 仅 Edge 网页:www.bilibili.com 等;其余 NULL
);
CREATE INDEX idx_fg_time ON foreground_segments(ts_from);
CREATE INDEX idx_fg_app  ON foreground_segments(app_name, ts_from);

-- ③ 日汇总(长期保留,驱动统计与概览)
CREATE TABLE daily_stats (
  day        TEXT NOT NULL,           -- 'YYYY-MM-DD'
  app_name   TEXT NOT NULL,
  fg_sec     INTEGER NOT NULL,        -- 前台(使用)秒
  total_sec  INTEGER NOT NULL,        -- 运行总秒(含后台)
  sessions   INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (day, app_name)
);
```

Edge 站点的“使用时长”= 对 `foreground_segments.domain` 过滤后按 domain 聚合;**不单独建 URL 表、不存完整 URL**。

### 4.3 体积控制(长期不膨胀)

| 手段 | 说明 |
|---|---|
| 事件化写入 | 前台只在**变化**时落行(切前台/锁屏/退出/每分钟 checkpoint),不写心跳 |
| 日汇总 | 每小时增量折叠进 `daily_stats` |
| 分层保留 | 明细默认保留 90 天滚动清理,汇总永久;保留期可配 |
| 体积预估 | 明细约几十 KB~几百 KB/天;90 天 < 50 MB;压测注入 365 天 < 100 MB |
| Edge URL | 只落规范化 host,不存 URL/标题原文(隐私 + 体积双赢) |

### 4.4 可靠性(不丢数据)

1. 片段封口即写;每分钟强制 checkpoint;
2. 进程退出事件 → 立即封口对应运行会话;
3. 启动对账:封口所有 `ended_at IS NULL` 会话(按上次心跳/上次关机时刻,标 exit_kind=2);
4. 单写者(采集引擎唯一写者),查询只读。

### 4.5 自动备份(硬需求)

| 项 | 设计 |
|---|---|
| 触发 | 每日 1 次(默认开机后首次空闲或 02:00);升级/重大变更前额外备份;CLI 可手动 `usage backup` |
| 方式 | `VACUUM INTO '<backups>\usage-YYYYMMDD-HHmmss.db'`(一致性副本,不锁主库) |
| 保留 | 最近 **30** 份自动滚动清理(可配) |
| 自检 | 备份前对主库 `PRAGMA integrity_check`,失败则跳过当日备份并在托盘告警 |
| 恢复 | 启动自检主库损坏 → 托盘提示,一键用**最近一份完好备份**恢复(恢复前先自动再备份损坏库留证) |

## 五、统计与展示

### 5.1 核心查询(SQL 均可测)

```sql
-- 某日使用时长(前台) Top
SELECT app_name, SUM(ts_to-ts_from)/1000 AS fg_sec
FROM foreground_segments WHERE ts_from>=? AND ts_to<=?
GROUP BY app_name ORDER BY fg_sec DESC;

-- 某应用某日总运行时长(含后台)+ 使用时长
SELECT s.app_name, SUM(s.ended_at-s.started_at)/1000 AS total_sec,
       (SELECT SUM(f.ts_to-f.ts_from)/1000 FROM foreground_segments f
         WHERE f.app_name=s.app_name AND f.ts_from>=? AND f.ts_to<=?) AS fg_sec
FROM process_sessions s WHERE s.started_at>=? AND s.ended_at<=? GROUP BY s.app_name;

-- Edge 站点使用时长(近 30 天汇总)
SELECT domain, SUM(ts_to-ts_from)/1000 AS sec FROM foreground_segments
WHERE domain IS NOT NULL GROUP BY domain ORDER BY sec DESC;
```

### 5.2 展示落地

- **托盘**:图标 + 悬停“今日使用 Xh Ym”;单击弹窗:今日总使用、前台 Top5、当前应用、今日 Top 站点;右键菜单:今日概览 / 近 7 天排行 / CLI 入口 / 备份与恢复 / 忽略名单 / 退出。

## 六、关键难点与对策(v2)

| 难点 | 对策 |
|---|---|
| 权限 | 前台轮询 + NtQuerySystemInformation 快照 + UIA 均不需管理员;拒绝提权、拒绝服务安装;受限读取不到时用快照映像名兜底 |
| PID 复用 / 识别覆盖率 | (PID, CreateTime) 稳定主键;白名单 + Session 过滤;覆盖率目标:所有“前台可见应用”100% 按正确名字计费,个别保护进程降到名字级 |
| 误计费(口径) | 同一时刻只认一个前台;锁屏/UAC/睡眠不归属;后台时段只算运行时长不算使用;不引入输入/空闲这种不可复现的判定 |
| Edge 域名可靠性 | UIA 读地址栏为主 + 标题正则兜底 + “未知页面”兜底;M0 spike 实测后定稿该链路(3.4) |
| 隐私 | 纯本地不联网;无窗口标题;Edge 只存规范化 host 不存 URL;忽略名单(银行/密码管理器等不入统计);数据目录随用户 |
| 数据安全 | 4.5 自动备份 + 自检 + 一键恢复,丢失窗口 ≤ 1 分钟且有备份兜底 |

| T9 | 资源/体积 | 24 h CPU 平均 <0.5%、内存 <100 MB;压测注入 365 天数据 DB <100 MB,Top/趋势查询 <500 ms |
| T10 | 一致性 | `integrity_check` 通过;相邻前台片段无重叠无空洞(ts_from==上条 ts_to) |
| T11 | 自动备份 | 手动制造主库损坏 → 启动自检告警,一键恢复至最近完好备份且数据不晚于损坏前 1 天;备份目录滚动保留生效(旧备份被清理、完好备份保留) |
